飞牛长文件名自动同步（Windows 10/11 x64）
========================================

目标：Windows 原文件一律不改名；普通名称原名上传；超过 NAS 文件系统 255 UTF-8 字节的文件/目录名，在 NAS 上使用唯一短名称；恢复时根据映射恢复原始名称。无需 Python。

重要：本程序是独立的单向备份工具，不是对“飞牛同步”客户端的插件。使用前必须确保飞牛 NAS 开启 SMB 文件共享，并且 Windows 资源管理器可进入 NAS 共享文件夹（如 \\192.168.1.100\Backup）。建议为本程序新建专用 NAS 共享子文件夹。

第一次使用：
1. 双击“飞牛自动同步_长文件名兼容版.exe”。
2. 选择“电脑源文件夹”（原始文件，不作修改）。
3. 选择“NAS 共享文件夹”（例如 \\192.168.1.100\Backup\工作资料，必须已经存在）。
4. 点击“立即同步一次”，先检查日志与 NAS 内容。
5. 点击“开启自动同步”，程序运行时每隔约 1 分钟自动扫描新增和修改内容。
6. 可选：点击“设置开机启动”，以便登录 Windows 时自动启动并同步。关闭程序则不会继续自动同步。

恢复：
1. 确保 Windows 能访问同一个 NAS 备份目录，含“__FN_ORIGINAL_NAMES__.json”。
2. 点击“原名恢复”，选择电脑上目标文件夹。
3. 自动恢复原始完整文件名和目录层级，数据按 SHA-256 校验，不会覆盖不同内容的同名文件。
4. 若 Windows 无法创建超长完整路径，可能需要开启 Windows 长路径支持（此程序不会擅自修改系统设置）。

行为说明：
- 普通文件保持原始名称和相对路径，仅超长名称会生成 _FN_LONG_... 短名称。
- 会扫描所有源文件（才能识别变化），但不会重新传输未变化文件；不会复制整份中转文件到本机。
- 此程序仅上传，不会根据源文件删除而清理 NAS 端旧文件；用于安全备份，不是双向镜像。
- 切勿删除或手动编辑 NAS 目录内的 __FN_ORIGINAL_NAMES__.json 及其 .previous 文件。
- 不要将原始 Windows 源目录作为 NAS 目标的子目录，也不要让本程序的两个目录相互包含。
- 如果原来的飞牛同步任务仍指向同一个源目录，原客户端仍会报“文件名过长”；请先暂停旧任务，测试成功后再停用。
- 使用 SMB 时 Windows 需能直接访问 NAS；不支持仅使用飞牛 ID 在外网无 SMB/VPN 的环境进行传输。
- 确保 NAS 有足够空间；本程序不会删除已有 NAS 数据，并在恢复时保留同名冲突文件。
- 程序是非签名便携 EXE，可用于自测；建议先用小范围样本验证后正式使用。

故障排查：
- “无法访问 NAS 文件夹”：先在 Windows 文件资源管理器输入共享路径，确认可打开且有写入权限。
- “同步失败”：检查程序下方日志、网络、NAS 空间/权限。
- “恢复找不到映射”：必须备份整个 NAS 目标目录，尤其是 __FN_ORIGINAL_NAMES__.json。
- 目标文件已存在且不同内容：程序会跳过，不会覆盖；改用一个空目录恢复。

技术：Go 编译的 x64 Windows 原生 GUI，核心代码使用标准库；文件内容不经第三方云服务。
