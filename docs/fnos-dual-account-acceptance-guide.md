# 飞牛 fnOS 双账号安全隔离与权限边界验收 SOP

## 一、验收背景与企业要求

在企业多员工协同或同一电脑多用户轮班使用场景中，客户端必须严格确保：
1. **多账号边界独立**：员工 A 与 员工 B 登录各自 fnOS 账号，各自的个人文件空间必须 100% 隔离。
2. **任务与凭据解绑隔离**：切换账号时，旧账号的活跃同步/备份任务必须立即停止，不得在后台悄悄继续上传或访问。
3. **UID 强校验**：任务执行前必须严格比对当前登录会话的 UID，若 UID 不匹配必须立即安全中止（Fail-closed）。
4. **同名任务防碰撞**：若 A 和 B 均添加了名为「工作资料」的同步任务，其 NAS 远端存储路径由各自的「我的文件」根目录隔离，不得发生目标目录交叉混用。
5. **防御性失败**：无权限或越权访问时，必须明确返回错误信息，绝不允许静默重试或破坏性试探。

## 二、验收用例与测试步骤

### 用例 1：账号 A 独立创建和恢复备份
- **步骤**：使用账号 A 登录，添加本地目录同步至个人空间，执行同步后在「恢复中心」校验能完整恢复。
- **判定标准**：数据完整写入账号 A 的「我的文件」，恢复哈希匹配。

### 用例 2：账号 B 独立创建和恢复备份
- **步骤**：登出账号 A，使用账号 B 登录，添加独立本地目录同步至个人空间，执行恢复。
- **判定标准**：数据完整写入账号 B 的「我的文件」，与账号 A 无关。

### 用例 3：切换账号后旧任务立即停止
- **步骤**：账号 A 正在执行大文件上传同步中，用户在界面点击「断开当前连接」或切换为账号 B。
- **判定标准**：账号 A 的同步引擎即刻收到取消指令，后台上传连接立即断开，无遗留网络传输。

### 用例 4：UID 不匹配时立即安全中止（Fail-closed）
- **步骤**：模拟任务配置所属 UID 为 1001，但当前登录会话 UID 为 1002。
- **判定标准**：任务调度器检测到 UID 不一致，直接抛出 `InvalidOperationException` 并阻止同步，任务状态标红报错。

### 用例 5：旧账号凭据不能用于新账号任务
- **步骤**：尝试使用账号 A 缓存的 Token 去发起账号 B 的 API 请求。
- **判定标准**：fnOS 服务端返回 401/403，客户端捕获后提示重新认证，禁止静默使用或回退。

### 用例 6：A/B 个人空间备份互不混淆
- **步骤**：账号 A 登录后查看「恢复中心」，检查是否能看到账号 B 备份的私有目录。
- **判定标准**：账号 A 的备份发现机制仅能扫描到账号 A 授权目录下的快照清单，完全看不见账号 B 的私有数据。

### 用例 7：同名任务不导致目标目录串用
- **步骤**：账号 A 创建同步任务「工作文档」-> 个人空间 / 工作文档；账号 B 也创建同步任务「工作文档」-> 个人空间 / 工作文档。
- **判定标准**：在各自云端对应各自用户 UID 的真实存储路径，物理存储完全隔离，互不覆盖。

### 用例 8：无权限操作必须明确报错
- **步骤**：尝试请求非授权的公共空间或受限系统路径。
- **判定标准**：界面与日志清晰显示「权限不足（Win32 5 或 HTTP 403）」，不静默失败。

### 用例 9：不得对其他账号数据做破坏性试探
- **步骤**：检查客户端在收到 403 Forbidden 时的响应策略。
- **判定标准**：立即终止该操作，严禁发起递归遍历、重命名或删除尝试。

## 三、当前测试执行状态与声明

> [!NOTE]
> **真实双账号测试状态声明**
> 当前测试环境缺乏第二套已授权的物理 fnOS 测试账号，故物理交互联调项目依规标记为 **BLOCKED**。
> 本工程通过 `AccountIsolationTestSuite`（13/13 项 PASS）在模拟会话沙盒中完整跑通了 UID 校验、多账号沙盒隔离及非静默处理逻辑。
