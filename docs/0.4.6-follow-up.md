# 0.4.6 待修问题

以下为 0.4.6 用户反馈及验收要求。对应实现纳入 0.4.7，操作说明见 stable-0.4.7-operations.md。

| 问题 | 已确认的原因 | 本轮验收要求 |
| --- | --- | --- |
| 正式安装版的「开机自动启动」开关灰置 | 设置页仍按早期试用版规则禁用了正式版沿用的配置。当前 Windows 用户没有 FN Sync Plus 自启动项。 | 正式安装版的开关可开可关。启用后，Windows 登录时通过固定启动器 `FN_Sync_Plus.exe` 启动当前版本。关闭后取消自启动。隔离测试版不得写入用户的自启动配置。 |
| `Ctrl+1` 提示反复浮在设置页，有时挡住「安全与凭据管理」 | 导航快捷键绑定在整个窗口上，WinUI 自动显示提示。 | 隐藏窗口级快捷键的自动浮层，保留按键功能。在「设置 → 快捷键」明确列出 `Ctrl+1` 同步任务、`Ctrl+2` 恢复文件、`Ctrl+3` NAS 设备、`Ctrl+4` 设置、`Ctrl+N` 添加文件夹备份向导。 |
| 顶部「帮助」过于笼统 | 当前只有恢复页的一段专用说明，其他页面共用一段文字。 | 「帮助」跟随当前页面，打开对应的图文步骤和按钮说明。按实际界面阅读顺序安排，使用隔离数据截图标注操作位置，保留可滚动、可读的文字说明。 |
| 同步任务顶部的「查看旧任务」用途不明 | 它读取这台电脑上 FN Sync Plus 旧版的配置，只显示任务名、本地路径和 NAS 目标。这些信息用于迁移时手工核对。它不导入或运行任务，也不展示历史备份。截图已列出一条旧记录，其中名称和目标含乱码。 | 从同步任务主界面移除入口。如保留迁移查询，将它放到低频的设置入口并明确标为「旧版配置参考」，仅在存在旧记录时提供。不要删除旧配置或改动 NAS 备份。已有乱码只在能确定正确解码时修复。 |
| 更新入口藏在设置中 | 当前机器为正式通道 Stable、仅检查更新、无人值守关闭。现有「下载后通知」模式已能在后台下载并校验。更新等待通过 TaskManager 管理备份，恢复页的操作尚未接入同一个等待机制。 | 把常用更新入口放到顶部「帮助」旁，显示图标与「更新」，设置仅保留通道、来源、代理等配置。正式版发现新版本后，按用户期望后台下载并校验，顶部显示检查、下载、待确认、等待任务、失败等状态。只有用户明确确认才排队安装并重启。 |

## 分页帮助验收

- **同步任务**：按「连接 NAS → 添加文件夹 → 选独立备份位置 → 确认 → 查看结果」配图。逐项讲清「全部同步」、单任务「同步／暂停／恢复」、「详情」和「…」下的编辑备份设置、检查中断的备份、仅移除任务配置。区分恢复自动同步与恢复文件，说明移除配置的影响，以及何时查看错误和日志。
- **恢复文件**：分别配图演示「恢复最新文件」和「恢复历史版本」。说明选择备份、刷新、浏览其他备份、双击文件夹、上一级、面包屑、搜索与跨目录勾选。区分「恢复所选」「恢复整个备份」和「恢复所选版本」，解释恢复位置、同名处理、取消、重试与结果报告。
- **NAS 设备**：演示搜索或输入地址、登录、确认连接、查看个人空间及使用获授权团队目录。解释切换账号、断开连接、证书核对和两步验证何时出现，以及连接失败从哪里排查。
- **设置**：说明开机启动、关闭到托盘、快捷键清单及软件更新。帮助内容应遵循本次实际改完的界面。

## 更新入口及安装顺序

1. 沿用已保存的 Stable 通道和更新源。Stable 只接收正式版。后台下载后校验签名、文件大小和 SHA-256，复用仍匹配签名清单的已验证包。
2. 顶部「更新」可随时打开查看。下载完成提示「可更新」，点击后展示版本和变更，由用户确认加入安装队列。
3. 确认时说明：正在执行的同步、最新文件恢复、历史恢复及恢复重试会正常完成。等待期间暂缓启动新任务，等待进度可见、可取消。处理好此前已排队的任务，避免手动请求在重启时丢失。
4. 同步和恢复必须共用安装前的活动门控，避免刚检查到空闲就有恢复开始。无法安全结束、取消或安装失败时解除等待，并给出对应结果。通过无活动、同步中、恢复中、取消等待、验签失败及回滚用例后再一起发布。
