# FN Sync Plus 接手审计与整改记录

基准：PR #2 `fab1b26598b30455ba4683e491daccb4fe2cb9e9`。本分支是未完成的安全整改草稿，不能作为可靠备份版本或正式发行版使用。

## 已确认问题及本轮修改

- `AppSettings.Load` 原先按名称、路径和 ID 删除任务并保存；现停止自动清理，损坏配置读取失败直接报错；迁移前保留独立备份，保存采用临时文件替换。可疑任务提醒及用户确认删除的专门界面尚未实现。
- `ManifestManager` 原远端流程先覆盖主清单；现先上传独立候选并回读 SHA-256，再备份旧主清单并校验，最后写主清单并校验。主备都不可读时拒绝返回空清单；主文件损坏、备份可读时会回退。该流程仍不是完整的版本选择/提交协议，未解决跨设备并发、远端一致性及旧数据对象被覆盖的问题，不能称为原子提交。损坏主文件时写入拒绝继续，避免覆盖可能唯一有效的备份。
- `FnOsPersonalStorageProvider` 原将目录列表错误视为不存在；现在失败响应与读取异常向上传递。真实 fnOS 的目录缺失、返回格式及网络异常仍需设备验证。
- `RestoreEngine` 原历史及重试路径无条件覆盖、缺少路径检查；现默认跳过，支持显式覆盖或重命名，校验路径和 SHA-256。普通本地恢复改为只枚举活动清单。目录重解析点检查是尽力防护，不能消除并发替换目录带来的竞态；历史对象本身是否不可变尚未得到保障，UI 尚未接通历史恢复。
- `SyncEngine` 的最终清单保存异常不再被降级为警告；本地路径有失败文件时不再报告 Completed。
- 测试用样本不再默认读取固定真实目录，图标测试写入独立临时目录；新增 `--integrity-regressions`。首轮测试曾触发旧清单缓存代码，创建 `%LOCALAPPDATA%\FNSyncPlus\manifest_cache\backup\manifest.json`，已去除缓存写入，文件保留未删除。

## 仍有 P0 风险

1. `SyncEngine.DetectRenamesAndProcessDeletions` 上传前在内存移除活动项并只记录原存储路径；历史没有不可变对象。离线重复内容不能唯一配对时现中止并保留旧清单，但尚无界面处理待确认差异。Smart、Archive、Mirror 未完成物理语义。现有内容更新仍可能覆盖旧对象，清单安全写入并不能保证旧备份可恢复。
2. 缺少扫描、准备、验证、提交的完整事务；失败或取消时现不提交本批次新清单，但之前写入的远端活动文件可能已被覆盖；断电和并发仍不能保证先前有效状态。
3. 稳定性等待失败时已停止同步，但尚未使用任务级延迟，且检查后上传期间源文件仍可能变化。自动调度、暂停、重连、监听器生命周期和界面状态尚未完成审计与修复。
4. 本地清单替换和远端主/备切换仍依赖底层存储行为，跨设备锁和版本排序未验证；不可把本轮主备测试推广到所有故障模式。
5. 恢复路径和错误状态仍需完整审计，包括旧清单无哈希的兼容策略、独立错误记录和取消状态。现对无哈希文件拒绝恢复，因此老备份兼容性尚未验收。
6. 全量测试仍使用默认日志、部分本机探测和其他非统一的测试路径；隔离改造未完成，不能在用户环境直接运行。必须补齐用户列出的全部回归及真实 NAS 测试。

## 手动设备测试会话

WinUI 传入 `--isolated-test-session` 时使用内存配置，不加载正式任务，仅在用户勾选“记住凭据”时，将凭据加密保存在独立测试命名空间，不覆盖正式凭据。此模式仅用于隔离诊断，进程退出后任务配置会消失，不能替代重启后补偿扫描验收。测试必须使用明确授权的唯一 NAS 沙盒，不能修改或删除既有目录。窗口标题包含“隔离测试会话”。

隔离会话现可用单独保存的加密凭据自动连接，并只读复用正式设置中已经信任的有效 SHA-256 证书指纹；证书变化、配置损坏或不明确时不会自动信任。真实飞牛使用隔离凭据副本测试连接，原隔离凭据文件和正式设置文件前后哈希不变。自动连接不适用于正式会话；二次认证或新证书仍需用户处理。

2026-11-06 设备诊断：在隔离 WinUI 会话中，实际选择文件夹后 `Windows.Storage.Pickers.FolderPicker.PickSingleFolderAsync` 抛出 COMException，导致选择结果丢失、下一步不可用。现已切换至 Windows App SDK 的桌面 FolderPicker，编译通过；实际界面回归待验证。隔离测试会话曾发现登录成功会走清除正式凭据分支，已在重新登录前修复；检查时原有 `credentials.dat` 仍在。

后续真实设备诊断中发现，本分支新增的 `file.ls` 响应校验错误地要求 `result` 字段，导致有效列表被拒绝；已修正为允许无 `result` 但包含文件数组的响应，仍拒绝明确失败和空响应。新增回归共 11 PASS，真实目录读取待重新验证。

## 托盘与下一步安全整改

WinUI 现支持关闭窗口后隐藏至托盘、双击托盘图标恢复和托盘菜单退出；关闭该设置后窗口关闭将退出。空隔离会话中已实际验证这四项，尚未在已连接真实 NAS 的任务上验证隐藏期间自动同步。`--minimize` 启动参数可隐藏窗口；重启后的连接与补偿同步仍需验证。

本地/SMB 目标排他锁获取失败时现在中止，不再继续写入；飞牛账号未连接时任务进入等待状态，避免将个人空间相对路径误当本地目录；活动飞牛连接不再接管本地或 SMB 任务。上传失败或取消时不再提交部分清单；隔离故障注入覆盖了重命名新文件上传失败或取消时保留旧清单记录。**这不能保护此前已被原位覆盖的文件内容**，不可变内容和完整事务仍是 P0。

## 实验性清单和内容对象（尚未接入备份流程）

新增 `VersionedManifestStore`：唯一候选回读 SHA-256 后写入唯一提交记录，读取时验证并选择最新有效序号；检测到同一序号的多个有效提交时拒绝选择。候选或提交记录不完整时可回退已有有效版本，但发现无效记录后拒绝继续写入。若提交已写入但上传响应丢失，本次结果是不确定而不是一定未提交，必须重新读取。格式错误、源读取失败和过期写入均有隔离测试。

## 2026-11-09：迁移、恢复和锁的隔离验证

- 新增 `LegacyBackupMigration` 实验流程：仅接受可读取、结构有效且所有活动及历史文件具有有效大小与 SHA-256 的 v3/v4 主清单。先将旧文件复制到独立对象并校验，再核对旧主清单未改变，最后提交版本化清单；旧主清单和旧文件不被修改。失败、取消、源文件损坏和旧清单中途变更均有隔离回归。缺失哈希、损坏主清单或不受支持的版本直接拒绝，尚无用户界面处理。
- 新增显式 `RunRestoreVersionedAsync` 实验入口，复用恢复校验与冲突处理，测试了当前文件、空目录、历史文件及默认跳过冲突。远端恢复在取消时清理临时文件并传播取消；不安全目录记录在恢复前拒绝。恢复中心现通过新的包恢复接口接入版本化清单读取；迁移未接入正式任务，增量仅接入内存隔离测试任务。
- 恢复取消后的临时文件清理若失败，会同时报告取消与清理错误，不再静默忽略；正常取消不会提交最终文件。
- 本地/SMB 恢复的取消会向上传播，哈希失败和其他错误按文件记录；部分失败、全部失败与跳过现有文件使用不同状态。WinUI 恢复与重试使用实际结果，避免把跳过说成全部恢复成功。此处已编译，尚未完成真实 WinUI 逐项验收。
