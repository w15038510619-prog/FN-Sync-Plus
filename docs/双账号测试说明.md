# 双账号测试说明

本项由两个授权飞牛测试账号的持有人配合。为每个账号建立各自的「我的文件」顶层测试目录，名称以 `Codex_FN_Test_` 开头。在 B 的目录放一个无敏感信息的文本样本，让程序能确认 B 访问的是实际存在且非空的目录。

## 运行

打开解压后的 `acceptance` 文件夹，在地址栏输入 `powershell` 后回车。填写同一 NAS 的真实 HTTPS 地址与端口，以及两个独立账号的测试目录名称。

```powershell
$server = Read-Host "飞牛 HTTPS 地址和实际端口"
$a = Read-Host "账号 A 的顶层测试目录名称"
$b = Read-Host "账号 B 的顶层测试目录名称"
.\FNSyncPlus.AcceptanceRunner.exe --test-dual-account-live --server $server --root-a $a --root-b $b --authorize-nas
```

这是只读检查。测试工具依次在控制台询问账号。由账号本人输入密码和可能出现的验证码，输入时字符隐藏。需要证书指纹时，先向设备管理员独立核对，再添加 `--cert-sha256` 和 64 位十六进制指纹。

双方允许在各自沙盒内创建子目录和备份测试文件后，可在命令末尾加 `--allow-test-writes`。程序会在两个沙盒内各创建一份唯一编号的同名任务备份，并从 NAS 读回各自的标记。远端结果留在沙盒供检查。

## 看结果

| 项目 | 验收条件 |
| --- | --- |
| AuthA、AuthB、DistinctUid | 两次真实认证都拿到服务端 UID，且两个 UID 不同 |
| TokenIsolation | 账号 B 成功读取实际非空目录，使用 A 的会话请求同一地址时服务端明确返回权限拒绝。空目录、找不到目录、连接失败和未知响应均不能证明隔离 |
| SameNameTasks | 两个实际调度任务成功，各自的目标目录归属正确，且读回的样本内容匹配 |
| RequestAudit | 两个已完成的任务都有请求方法轨迹，操作可分类且没有删除请求。报告只包含方法计数 |
| WorkerStop | 仍需验证账号切换或断开时，正在运行的旧账号任务能否停止。当前运行器会将这项留为 BLOCKED |

账号不足时，所有真实项均应返回 BLOCKED。出现 FAIL 时，请保存 JSON 结果及复现步骤。反馈前请检查截图和日志，移除密码、验证码、Token、Cookie 与私有地址。
