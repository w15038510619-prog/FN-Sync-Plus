# 故障排查与恢复说明

## 1. 先看哪里

| 现象 | 首查位置 |
|---|---|
| 任务失败 / 状态异常 | 「任务详情 → 日志」，按批次号筛选 |
| 程序打不开 | `%LOCALAPPDATA%\FNSyncPlus\logs\crash_*.log` |
| 更新失败 | `<安装根目录>\update.log` |
| 备份内容对不对 | 「恢复中心」→ 选中备份包 → 校验 SHA-256 后恢复到空目录 |

导出诊断包时会自动脱敏：密码、令牌字段被替换为 `******`，日志中不写入凭据。

## 2. 常见问题

### 2.1 提示「存在结果不明确的提交或未释放的锁」

说明上一次备份在提交阶段被打断。程序不会猜测，也不会自动抢锁。

1. 确认没有其他设备或旧版客户端在写同一个备份目录；
2. 「任务详情 → 恢复检查」做只读检查；
3. 确认写入者已停止后，按提示输入确认文字解除遗留锁；
4. 不要手工删除 `.fnsync` 下的锁或对象目录。

### 2.2 模糊重命名导致备份停止

同一内容出现多个改名候选时，程序停止并保留上一份备份，不会猜配对。

1. 打开任务详情，查看「待处理差异」：原文件、候选新文件、大小、SHA-256、原因；
2. 确认真实对应关系后选择候选并确认；
3. 确认前程序会重新哈希当前文件；若内容已变化会要求重新扫描。

### 2.3 NAS 连不上

- 检查地址、账号大小写、UID 是否与任务创建时一致；
- UID 不一致或未知时任务是 fail-closed 的，不会写数据；
- 证书指纹变化需要在设备页重新确认，程序不会静默信任新证书。

### 2.4 恢复时部分文件失败

恢复是逐文件校验的：任一文件哈希不符就报告失败，不生成最终文件。失败清单在恢复结果里。链接/联接点目标路径会被拒绝写入。

### 2.5 更新后程序打不开

1. 更新器会自动回滚一次并启动旧版本；
2. 若仍失败，手工回滚：`FN_Sync_Plus.exe --layout <安装目录> --rollback`；
3. 查看 `update.log` 中的 `launch ... not healthy` 原因；
4. 若提示「配置由更高版本写入」，说明数据格式已升级，不要强行降级，安装最新版本。

### 2.6 磁盘/NAS 空间不足

「设置 → 备份容量与保留策略」可只读统计当前备份、历史版本、物理对象与未被引用的对象。

**程序不会自动删除历史版本。** 预览只给出建议，且会明确说明：删除旧版本记录通常不会释放空间，因为历史对象仍被当前清单的历史记录引用。任何清理都需要单独评审。

## 3. 绝对不能做的事

- 不要递归删除 `.fnsync` 或任何未知对象目录；
- 不要用旧的不安全引擎替代新版引擎“修一下”；
- 不要在未确认写入者停止时抢锁；
- 不要把测试通过当作正式验收通过。

## 4. 恢复演练建议

每月至少一次：选一个测试备份 → 恢复到空目录 → 逐项核对文件名（含长中文名）与 SHA-256 → 记录结果。正式资料必须有独立于本程序的第二份备份。
