# 0.4.4 Stable 安装、恢复与更新

构建与验收结果以本轮交付报告为准。本说明本身不代表发布已经完成。

## 安装与配置保留

使用 `FN-Sync-Plus-0.4.4-Windows-x64-Setup.exe`。先等待备份结束，通过托盘退出旧程序，再运行安装程序。安装器会保留旧版本程序目录、原配置、凭据和 NAS 备份。

0.4.4 继续使用原来的 `%LOCALAPPDATA%\FNSyncPlus\versioned-beta` 配置位置。这个目录名是兼容路径，不表示仍使用旧引擎；不要自行改名或删除。用户名、任务标识、源目录、目标目录及历史格式均沿用。更高或不兼容的格式仍会被安全拒绝。

安装程序当前没有 Windows Authenticode 签名。更新清单的 ECDSA 签名用于验证更新来源，不能代替 Windows 代码签名。

## 日常备份

1. 在“NAS 设备”登录自己的飞牛账号，核对地址和证书。
2. 在“同步任务”添加本地文件夹，选择“我的文件”或已授权的团队文件作为备份父目录。
3. 软件为任务规划独立子目录，确认后备份。不同设备不要写入同一个备份目标。

团队文件通过 fnOS 已开启的 SMB 服务访问。当前已验证的团队共享由 NAS 公布为 `团队文件-<名称>`；界面去掉这一前缀，例如显示 `cenco-public`。个人文件夹映射和普通 SMB 共享不会因为可访问就被归入团队文件。服务器权限决定能否读取或写入；软件不会扩大权限。Windows 若已用其他账号连接同一 NAS，软件会拒绝凭据冲突，不会强行断开其他网络连接。

Excel/WPS 文件保存后可保持打开。允许共享读取时，程序备份经核验的临时稳定副本；未保存的内存修改不会被备份。独占占用或持续变化的文件会延迟或失败，本次未确认的内容不会冒充成功提交。临时副本按块处理，磁盘需有容纳当前待上传文件的空间。

## 恢复

1. “恢复文件”自动显示当前任务关联的备份；换电脑或恢复其他备份时使用“浏览其他备份位置”。
2. 选择“恢复最新文件”或“恢复历史版本”。可搜索原文件名、浏览文件夹、选择多项；历史行显示具体日期时间，并支持按日期筛选。
3. 选择本地文件夹。默认使用新的 `FN-Restore-时间` 目录，同名文件默认跳过。
4. 核对确认窗口里的版本、文件和目标位置，再开始恢复。覆盖同名文件需在确认窗口明确确认。内部对象地址只放在高级详情中。

恢复始终校验 SHA-256。失败时导出恢复报告，并在任务详情中查看诊断日志；不要手动修改备份内部的 `.fnsync` 文件。多个历史版本含同一文件时，默认跳过已有文件；需要同时保留时选择“重命名”冲突处理。

## 在线更新与回滚

新安装默认 Stable、仅检查、无人值守关闭。普通用户不需输入更新地址。官方地址为 `https://dev.sk-fj.com:8081/fnsync/stable/manifest.json`，实际部署和 HTTPS 校验结果须见交付报告。

更新地址、代理、超时和通道位于高级选项。0.4.4 仅将原来精确匹配的官方 Beta 地址切到官方 Stable，并显示迁移提示；其他自定义地址和策略保留。已有已验证缓存会重新核对签名、版本和文件 SHA-256 后复用。

更新器等待备份安全结束，保留原版本及回滚指针。启动健康检查失败会回滚。不要清理 `app-<旧版本>`、`previous.json`、`.ops`、更新日志、配置目录或 NAS 历史。无法自动恢复时停止同步，保存整个安装目录及日志，再按报告中的回滚记录处理。新增团队备份任务后，0.4.3 无法运行这些任务，不能强行降级；旧程序会拒绝不支持的任务配置并保留数据。安装健康检查阶段的自动回滚，与用户日后新增团队任务后手工降级，是不同的场景。

## 可复现发布

在受控 Windows 发布机、干净且已提交的工作树执行：

```powershell
.\tools\release\Build-StableRelease.ps1 -OutputRoot D:\FN-Release-044 -PublicKeyPath C:\ReleaseKeys\update-public.pem -PrivateKeyPath C:\ReleaseKeys\update-private.pem -Dotnet D:\dotnet\dotnet.exe
```

私钥必须在仓库和输出目录之外。构建器编译、运行完整性回归、生成应用载荷 ZIP、签署清单、用客户端内嵌公钥独立验签并制作安装器。

首次在 CentOS 建立 Stable 目录（不要覆盖现有 Nginx 配置）：

```bash
install -d -m 755 /data/fnsync-updates/stable
```

配置好受控 SSH 密钥后上传：

```powershell
.\tools\release\Publish-OnlineBeta.ps1 -Channel stable -ReleaseDirectory D:\FN-Release-044\delivery -SshTarget root@192.168.8.18 -PublicKeySha256 <实际公钥SHA256> -Dotnet D:\dotnet\dotnet.exe
```

上传脚本名称保留兼容性，`-Channel stable` 发布 Stable。CentOS `publish-beta.py --channel stable` 先核验并发布 ZIP，再验证 ECDSA、版本、URL 和 ZIP 哈希，最后原子替换清单。原 Beta 文件与旧清单历史保留；暂存区保持 root 所有、700，服务器只保存公钥。

已安装的 0.4.3 若仍只检查官方 Beta 源，需要在验收通过后由发布人员提供签名的 0.4.4 迁移更新，或手工安装 0.4.4。不能通过把旧包改名为 Stable 实现迁移。
